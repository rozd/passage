# Passage — NIST SP 800-63B AAL1 Conformance

This directory holds the artifacts backing Passage's **self-asserted AAL1 conformance claim** under NIST SP 800-63B rev 3 (2017, updated 2020).

> **This is not certification.** Passage has not been assessed or validated by NVLAP, FedRAMP, Kantara, or any accredited body. These documents are public engineering artifacts that let integrators verify Passage's handling of authentication requirements against the specification themselves.

## Headline artifact

- **[`CLAIM.md`](./CLAIM.md)** — the self-assertion. Read this first. Scope, threat model summary, cryptographic dependencies, residual risks, and a link to the conformance matrix as an appendix.

## Workflow (for maintainers)

The conformance artifacts are built by a three-phase Ralph-style workflow:

1. **Decompose once** — `/aal1-decompose` populates `requirements.yaml` from the SP 800-63B source document. One-shot; human-reviewed.
2. **Iterate tests** — `/aal1-add <N>` writes `N` tests against the next pending clauses (one commit per test). `/aal1-ralph` runs this autonomously until every testable clause has a test.
3. **Implement features** — failing tests enumerate the gap list. Features land in `Sources/Passage/` to turn red tests green.

The matrix in `conformance.md` is generated by `.scripts/generate-aal1-matrix.sh` from the ledger plus test files; CI diffs the committed matrix against a fresh regeneration.

### Ralph single-loop constraint

The Ralph Loop plugin allows **one active loop per project**. `/aal1-ralph` will refuse to start if another `.claude/ralph-loop.local.md` is present for a different task. Cancel the other loop first with `/cancel-ralph`.
